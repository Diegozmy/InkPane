# 固件真机验收清单

固件在 CI/host 上只能证明「能编译、解析和排版正确」；下面这些必须在真机上逐项过一遍。
建议准备：一块烧好固件的板子、能跑 InkPane 服务的电脑、同一局域网、串口日志。

## 前置

1. `hardware/tools/build.ps1 -Flash -Port COMx` 烧录成功（ESP-IDF v6.0.2）。
2. 串口看到 `boot:`、`power rails ready`、`epd init` 相关日志，无 panic。
3. 服务端 `HOST=0.0.0.0`，`/api/health` 可从电脑访问。

## 清单

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 首次上电（无 NVS 配置） | 屏幕显示配网说明；手机能搜到 `InkPane-XXXXXX` |
| 2 | 连接热点，打开 `192.168.4.1` | 表单页显示；保存后设备重启 |
| 3 | 等待一个网络周期 | 屏幕显示六模块真实数据；服务端日志出现 200 |
| 4 | 再等一个周期 | 服务端日志出现 304；屏幕没有整屏黑闪，分钟数正常跳动 |
| 5 | 控制台改一条待办/布局 | 下一周期 200；屏幕对应区域更新 |
| 6 | 在控制台轮换设备令牌 | 下一周期 401；屏幕保留，时钟区显示「令牌无效」；不会每分钟重试 |
| 7 | 断电再上电 | 冷启动强制 200 + 全屏刷新；时间与内容正确 |
| 8 | 上电时按住 GPIO5 两秒 | 进入配网；不保存直接重启仍使用旧配置 |
| 9 | 关闭 Wi-Fi 三个周期 | 屏幕保留，时钟区出现「离线」；恢复后自动清除 |
| 10 | 控制台设备页 | 出现温湿度、电量、RSSI、固件版本 0.1.0、最后在线时间 |
| 11 | 电池低于 20%（或模拟低电） | 时钟区出现「低电」；200 与 304 两条路径都把联网间隔拉长到至少 120 分钟 |
| 12 | 观察一整天 | 跨天后 200 + 全刷；局刷残影可接受；无死机/重启循环 |
| 13 | 静置观察定时唤醒 | 分钟级只有时钟区局刷，无整屏黑闪；ALDO3 保持供电，面板不复位（warm） |
| 14 | 短接/拔掉 RTC 纽扣电池使 OS 置位后上电 | 时钟显示「等待校时」而不是错误时间；联网 200 或 304 校准后恢复走时 |
| 15 | 让服务端返回超过上限的事件/课程/待办（32/16/8） | 列表标题计数为服务端总数，溢出时显示「还有 N 项」，不越界、不崩溃 |
| 16 | 模拟全刷失败（如断开面板 FPC 后恢复） | 失败时清空 ETag，下一次唤醒重新 200 + 全刷，不会卡在 304 |

## 需要记录的数据

- 冷启动全刷耗时、局刷耗时（串口日志或示波器）。
- 深睡电流（µA，注意面板 ALDO3 保持供电）与联网唤醒平均电流；据此校正 README 里的功耗预期。
- 连续局刷多少分钟后残影开始明显；据此调整 `CONFIG_INKPANE_FULL_REFRESH_INTERVAL`。
- 低温环境（如 5 °C 以下）的刷新与残影表现。

## 失败时先看

- 串口是否有 `BUSY timeout`、`display refresh failed`、`payload parse failed`。
- 服务端是否返回 `{ "data": ... }`；响应头是否带 `ETag`。
- 设备令牌是否含非十六进制字符；`api_url` 是否漏了 `http://` 或多了 `/api`。
- 板子是否真的能进入深睡（串口 `deep sleep for N s` 后应无日志）。
