# 固件真机验收清单

固件在 CI/host 上只能证明「能编译、解析和排版正确」；下面这些必须在真机上逐项过一遍。
建议准备：一块烧好固件的板子、能跑 InkPane 服务的电脑、同一局域网、串口日志。

## 前置

1. `hardware/tools/build.ps1 -Flash -Port COMx` 烧录成功（ESP-IDF v6.0.2）。
2. 串口看到 `boot:`、`power rails ready`、`epd init` 相关日志，无 panic。
3. 服务端 `HOST=0.0.0.0`，`/api/health` 可从电脑访问。

## 清单

| # | 步骤 | 预期 |
| --- | --- | --- |
| 1 | 首次上电（无 NVS 配置） | 屏幕显示配网说明；手机能搜到 `InkPane-XXXXXX` |
| 2 | 连接热点，打开 `192.168.4.1` | 表单页显示；保存后设备重启 |
| 3 | 等待一个网络周期 | 屏幕显示六模块真实数据；服务端日志出现 200 |
| 4 | 再等一个周期 | 服务端日志出现 304；屏幕没有整屏黑闪，分钟数正常跳动 |
| 5 | 控制台改一条待办/布局 | 下一周期 200；屏幕对应区域更新 |
| 6 | 在控制台轮换设备令牌 | 下一周期 401；屏幕保留，时钟区显示「令牌无效」；不会每分钟重试 |
| 7 | 断电再上电 | 冷启动强制 200 + 全屏刷新；时间与内容正确 |
| 8 | 上电时按住 GPIO5 两秒 | 进入配网；不保存直接重启仍使用旧配置 |
| 9 | 关闭 Wi-Fi 三个周期 | 屏幕保留，时钟区出现「离线」；恢复后自动清除 |
| 10 | 控制台设备页 | 出现温湿度、电量、RSSI、固件版本 0.1.0、最后在线时间 |
| 11 | 电池低于 20%（或模拟低电） | 时钟区出现「低电」；200 与 304 两条路径都把联网间隔拉长到至少 120 分钟 |
| 12 | 观察一整天 | 跨天后 200 + 全刷；局刷残影可接受；无死机/重启循环 |
| 13 | 静置观察定时唤醒 | 分钟级只有时钟区局刷，无整屏黑闪；ALDO3 保持供电，面板不复位（warm）。时钟必须**原地**跳动，不能在待办/课程区域或屏幕下缘出现时钟副本（面板栅极自下而上，局刷 `0x45/0x4F` 必须使用镜像后的 RAM Y：`HEIGHT-1-y .. HEIGHT-y-height`） |
| 14 | 短接/拔掉 RTC 纽扣电池使 OS 置位后上电 | 时钟显示「等待校时」而不是错误时间；常驻模式联网后由后台 SNTP 校准（`rtc calibrated from sntp: ...`），LOW_POWER 模式由 200 或 304 校准，两者都恢复走时 |
| 15 | 让服务端返回超过上限的事件/课程/待办（32/16/8） | 列表标题计数为服务端总数，溢出时显示「还有 N 项」，不越界、不崩溃 |
| 16 | 模拟全刷失败（如断开面板 FPC 后恢复） | 失败时清空 ETag，下一次唤醒重新 200 + 全刷，不会卡在 304 |
| 17 | 服务只监听 `127.0.0.1` 时上电 | 屏幕整屏显示「无法连接日程服务」，含本机 IP、服务地址与重试提示；控制台启动日志出现「当前只监听回环地址…」 |
| 18 | 改成 `HOST=0.0.0.0` 后按任意键唤醒 | 一分钟内 200 + 全屏刷新，提示页被真实内容替换，RTC 被校准 |
| 19 | 服务未启动 / 配网填错 IP | 同上提示页；重试间隔 60 s、120 s、180 s 递增（上限 10 分钟或刷新间隔），不会睡满 30 分钟 |
| 20 | 成功拉到一次屏幕后，按住滚轮「下」键约 1 秒再松手 | 全刷后显示下一个模块的整屏视图；串口出现 `zoom snapshot restored` 与 `zoom view N via gpio X`；日志里没有 Wi-Fi 连接（纯本地切换） |
| 21 | 放大态按滚轮「上」键、再按滚轮中键 | 分别切到上一个模块、回到总览；同样不联网。首次运行或刚配网时会看到 `zoom snapshot empty`，此时按键走联网刷新属预期 |
| 22 | 停掉服务后按键放大/翻页，再恢复服务 | 断网期间仍能离线切换总览与各模块页（数据来自 RTC 快照）；恢复后下一个网络周期刷新数据，当前视图保持不变 |
| 23 | 唤醒对话，观察状态变化（聆听 → 思考 → 回答） | 对话页只重画变化的整宽带，不再整屏闪刷；串口出现 `voice page partial refresh: N band(s), R rows, M ms`，状态标签变化通常 1 条带（约 30 行），回复多一行 1–2 条带（30–60 行）；屏幕无错位、无黑闪 |
| 24 | 一轮完整对话（新问题 + 新回答 + 状态都变） | 损坏超过预算（>3 条带或 >340 行），应回落全刷，日志 `voice page refresh (full=0 state=... outcome=2)`（`outcome`：0=无可见变化、1=带区局刷、2=全刷）；每轮大约一次，属预期 |
| 25 | 在对话页连续制造多次带区局刷 | 累计 40 次带区局刷后的下一次对话页更新强制全刷去残影（`s_voice_partial_updates >= RESIDENT_VOICE_FULL_EVERY`）；画面不残留灰底/叠影 |
| 26 | 冷启动（拔掉 RTC 备用电池，使 OS 位为 1）后联网，语音已启用 | 串口依次出现 `sntp service started (3 servers)`、`sntp synced: <epoch>`、`rtc calibrated from sntp: ...`；时钟从「等待校时」恢复走时。旧的 `sntp sync timed out` 警告**最多出现一次**，且只会在首次等待与一次立即重试都失败后出现。（若看板 200 先校准了 RTC、且语音未启用，SNTP 可能不启动，属正常的省电路径） |
| 27 | 让 UDP 123 出网被拦（只放行 TCP） | 应看到一次 `sntp sync timed out (will retry hourly in background)`，之后后台按小时重试；主循环每 60 s 在 RTC 未校准前补一次且不卡 UI；恢复出网后 RTC 应在数分钟内被校准（lwIP 的重试退避可能到 150 s 量级） |
| 28 | 说一句会让助手回答很长的提问（如「详细说一下明天的安排」） | 回复整段连续排版、按屏宽自动换行，一句里不会出现莫名其妙的分行或空行；字数多到 32 px 放不下时整体降到 24 px，仍能完整显示（六行放满即止）；只有实在超长时末尾才出现 `…`，内容不会被画到页脚分隔线以下或压住页脚 |
| 29 | 放大到时钟模块后静置 2 分钟（不要按键） | 分钟数字自己跳，不再需要「退出放大再重新放大」；日志每分钟一条 `zoomed clock refresh (digits band)`，屏幕只闪数字区域；跨天后出现一条 `zoomed clock refresh (full)` |
| 30 | 放大到日程/待办模块后，在控制台改一条数据 | 该放大页自动更新为新的列表内容（走 200 → `fetch_and_render` 的放大分支），无需按键退出再进入 |
| 31 | 唤醒对话，观察对话页出现的耗时 | 页面切换走 Fast 波形（`0x1A=0x6A` + `0x22=0xD7`），串口日志形如 `full refresh (fast): X ms total (Y ms transfer, Z ms waveform)`；记录 X 并与改造前（原 `0xF7` 普通档约 3–4 s）对比，目标是接近厂商参考的 ~1.5 s |
| 32 | 连续多轮对话后检查对话页残影 | 交互切换用 Fast 会留下更多残影，但累计 40 次带区局刷后会用普通波形整刷一次去残影（日志 `full refresh (normal)`）；真实观感应确认残影可接受 |
| 33 | 对一个词说「放大时钟」「放大日程」「看看天气」 | 助手回答后屏幕切到对应模块的放大页；串口出现 `voice zoom requested: module N` 与随后的放大重绘；对话页停留约 1.5 s 而不是 6 s；滚轮 4/6/5 之后仍可正常切换 |
| 34 | 说「返回总览」（已有模块处于放大态） | 屏幕回到总览；日志 `voice zoom requested: module -1` |
| 35 | 对控制台未启用的模块说「放大待办」 | 助手回「无法放大该模块：控制台未启用该模块」，屏幕保持原视图不闪；把「允许语音修改日程与待办」关掉后再问，`screen.zoom` 应完全不可用（工具列表只剩只读两项） |
| 36 | 长按 PWR 侧键约 2 秒 | 断电前先整屏显示「正在关机」、电池图形与「剩余电量 N%」；停留约 2 秒后断电（PMU 最迟 10 秒兜底）。串口出现 `power off (长按 PWR 关机): battery=... charging=...` |
| 37 | 接 USB 时重复长按 PWR；再在电量未知时观察 | 页面按实际状态显示「已连接 USB 电源」或「电量未知」，仍会正常关机，不会因为接 USB 而跳过 |
| 38 | 模拟电量 <5% 且拔掉 USB（或临时提高阈值） | 自动显示同一关机页，原因行为「电量过低（N%），自动关机」，随后断电；接 USB 时不自动关机 |
| 39 | 让助手回答一段较长内容，回答期间与刚结束时都不说话 | 回复必须完整播完才进入「聆听中」，不会中途断句或提前清空播放队列；状态按「正在回答 → 聆听中 → 待命」变化，中间不出现「待命」再跳回「聆听中」；之后 7 秒无追问回待命，日志出现 `continuous conversation: listening for a follow-up`；有追问时可直接继续，无需再说唤醒词 |

## 需要记录的数据

- 冷启动全刷耗时、局刷耗时（串口日志或示波器）。
- 对话页带区局刷的条数与耗时（日志 `voice page partial refresh: N band(s), R rows, M ms`），
  以及一次全刷回落（`outcome=2`）的耗时，用来确认 700 ms 节流真有余量。
- 深睡电流（µA，注意面板 ALDO3 保持供电）与联网唤醒平均电流；据此校正 README 里的功耗预期。
- 连续局刷多少分钟后残影开始明显；据此调整 `CONFIG_INKPANE_FULL_REFRESH_INTERVAL`
  （对话页对应的是 `RESIDENT_VOICE_FULL_EVERY`）。
- 低温环境（如 5 °C 以下）的刷新与残影表现。
- 首次 SNTP 同步耗时（从 `sntp service started (3 servers)` 到 `sntp synced:`），以及是否
  出现超时警告。

## 失败时先看

- 串口是否有 `BUSY timeout`、`display refresh failed`、`payload parse failed`。
- 服务端是否返回 `{ "data": ... }`；响应头是否带 `ETag`。
- 设备令牌是否含非十六进制字符；`api_url` 是否漏了 `http://`、多了 `/api` 或写成了 `https://`
  （固件不内置 TLS，串口会打印 `https is not supported`）。
- 板子是否真的能进入深睡（串口 `deep sleep for N s` 后应无日志）。
